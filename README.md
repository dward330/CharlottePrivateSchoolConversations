# Charlotte Private School Conversations

A parent-facing research tool for comparing **Charlotte-area private (K–12)
schools** side by side. It distils bulky source material — school websites,
philanthropy reports, athletic directories, IRS filings — into structured,
citation-backed cards a family can actually read, and presents the same research
in seven languages.

Built with **React 19 + TypeScript + Vite**.

---

## What it does

The app organizes research on six Charlotte independent schools:

- Cannon School
- Charlotte Christian School
- Charlotte Country Day School
- Charlotte Latin School
- Davidson Day School
- Providence Day School

across seven research topics that matter to families:

| Topic | What it covers |
|---|---|
| **Sports** | Teams offered, records, D1/pro pipeline, coaching, facilities, NIL |
| **The Arts** | The TK–12 arts ladder, theatre, music honors, visual arts, verdict |
| **Student Clubs** | Affinity groups, service, honor societies, a filterable club catalog |
| **College Support** | The transcript colleges see, the counseling engine, where graduates go |
| **Course Offerings** | Per-division course catalogs (Lower / Middle / Upper) |
| **After School** | Coverage map, a per-day cost planner, enrichment |
| **Financial Aid & Tuition** | A section-scored deep-dive: tuition bands, the real cost of attendance, the aid engine, published aid figures |

Three views:

- **Home** — the landing page and an overview of what can be explored.
- **Compare** — schools side by side, one research topic at a time.
- **School dossier** — every card for a single school, each expandable to a full
  research note with sources cited on every fact. An **Expand all** button opens
  every card at once (useful for printing).

## Design principles

**Every fact is sourced.** Cards link the underlying URLs, and the
data-provenance standard (see [`CLAUDE.md`](CLAUDE.md)) requires the hard data
behind any figure to be committed as a `.md` file under `source-material/`
before it reaches the app.

**Research enriches data, never the UX.** Ingesting new source material may add,
correct, or extend the data behind existing cards — but adding a new card,
section, or metric needs explicit approval first. This keeps the interface from
silently growing as a side effect of a research pass.

**Figures are never re-typed.** Tuition and dollar amounts are authored once,
US-style (`$28,500`), and re-formatted at render time. The currency always stays
USD and the amount never changes across languages — only the presentation is
localized. This makes it structurally impossible for a number to drift between
locales.

## Internationalization

The app ships in **seven languages** — English, Spanish, Bangla, Haitian Creole,
Telugu, French, and **Farsi** (the first right-to-left locale) — across two
deliberately separate text layers:

- **UI chrome** (nav, buttons, labels, captions) lives one file per language in
  `src/locales/<lang>.json`, reached through `react-i18next`.
- **Research prose** (~165k words in `src/data/**`) is *not* in the locale files.
  It is regenerated by the ingest pipeline, so it is translated at the data layer
  via content-hashed sidecar overlays (`src/data/overlays/`), with English as the
  fallback. An overlay entry only resolves if its stamp still matches the live
  English at that field path — otherwise the page falls back to English silently,
  which the check suite guards against.

Numbers, currency, and bidi handling all route through `src/lib/format.ts`. For
the full per-locale reasoning (why Farsi is in `FIGURE_SAFE_NUMBERS` on digits
alone, how RTL figures are LTR-isolated, why percent signs stay unspaced), see
`src/lib/i18n.ts` and the rollout docs in `.claude/docs/`.

## Getting started

Requires Node 20+.

```bash
npm install
npm run dev        # start the dev server (Vite, HMR)
npm run build      # type-check (tsc) + production build
npm run preview    # preview the production build
npm run lint       # oxlint
```

### i18n & data-integrity checks

The translation and data pipeline is guarded by a suite of checks:

```bash
npm run check:translations   # per-topic coverage, no drift
npm run check:hashes         # build-time vs runtime content stamps agree
npm run check:runtime        # every shipped overlay stamp recomputes from live English
npm run check:currency       # every money render site localizes
npm run check:money          # money-capable sites don't bypass the formatter
npm run check:bidi           # RTL figures isolate; LTR locales byte-identical
npm run check:fa             # Farsi: no Eastern-Arabic digit drift, ZWNJ intact
npm run check:fr             # French course-code identifiers stay Latin
```

## Project layout

```
src/
  components/     research-card bodies (Sports, Arts, Clubs, …)
  data/           structured research prose + per-locale overlays
  lib/            i18n, number/currency formatting, routing, manifest
  locales/        one JSON file per UI language
  pages/          Home, Compare, SchoolDetail
source-material/  committed .md source files (the provenance record)
.claude/docs/     rollout docs and reference material
scripts/          data-integrity and i18n check scripts
```

Project standards — the UX-design rule, the i18n architecture, the
data-provenance requirement, and the per-language translation history — are
documented in [`CLAUDE.md`](CLAUDE.md).
