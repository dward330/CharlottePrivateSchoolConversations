# Internal data consistency: all 13 schools

## Goal

Every school page should stop contradicting itself. Two cards on one page must not state
different values for what reads as the same fact, and no headline or tile may disagree with
the list beneath it. A difference that reflects a real difference in the sources stays,
labelled so it no longer reads as a contradiction.

A planning sweep of all 13 pages found **101 findings**. At the user's request (2026-11-20), the plan also
re-sources Providence Day's Middle and Upper School Course Offerings from the school's 2026–27 Course
of Study. The app was one edition behind; see [`consistency-data/pd-census.md`](consistency-data/pd-census.md). The fixes land in the data and, for
the College Pipeline, in a component that now computes the numbers. A new build gate,
`check:consistency`, keeps the derivable figures from drifting again.

Done means three things:
- the rebuilt pages show none of the A/B/C findings in
  [`consistency-data/findings.md`](consistency-data/findings.md);
- `npm run check:consistency` passes inside `npm run build`;
- the user has reviewed the English before any locale is touched.

## Context

### How the data becomes pages (deliverable 1)

**Three layers feed every school page.**

1. **Structured cards, hand-typed TypeScript.** This is where almost every parent-visible figure
   lives:
   - `src/data/<area>Programs/<slug>.ts` for admissions, after-school, arts, clubs, college
     support, sports and high-school placement;
   - `src/data/summer/<slug>.ts`, `src/data/internationalTravel/<slug>.ts` and
     `src/data/learningSupport/<slug>.ts`;
   - the one-file modules `src/data/courseOfferings.ts`, `financialAidReports.ts`,
     `clubCatalog.ts`, `clubClusters.ts` and `wellsFargoCup.ts`.

   Components in `src/components/*.tsx` render them, dispatched from `src/pages/SchoolDetail.tsx`.
2. **Compare cells**, typed in `src/data/metricValues.ts` (`VALUE_METRICS`). Each row is a key
   with per-school `values` and optional `quals` tooltips.
3. **Research prose cards**, GENERATED by the `ingest-source-material` skill
   (`scripts/build_site_content.py`) from `source-material/<topic>/<slug>/*.md` into
   `src/content/<topic>/<slug>.json`. On a school page these render only where a topic has no
   structured program, which today in practice means Financial Aid. Memory
   `prosecontent-unreachable-on-school-pages` has the detail. A fix there goes in the
   source-material `.md`, never the JSON. Sections headed `## Method` / `## Provenance` are
   dropped (`PROVENANCE_HEADING`). Sections split on `## ` only.

**Typed vs computed.** Nearly every count, total, ratio and "X of Y" is **typed by hand**:
- stat tiles;
- teasers ("122 courses across 13 departments");
- pipeline funnel `count` strings and `sportBars[].count`;
- camp intros ("60 of the 251 …");
- every Compare value.

Only a few figures are computed at render:
- list counters, such as the course list's "All departments N courses" and the camp chip
  "N of M camps" (`summerPrograms.campCount`);
- the After School cost-planner totals (`basis` × `periods`).

That split is the root of most findings: the typed figure was right when written, and the
list beneath it grew.

**Citations** sit on each card as `sources: { label, url }[]`. Each data file's header comment
names the `source-material/` record behind it, and the record carries the URLs and verbatim
quotes. Compare cells cite through their `quals` text and the per-school record.

**Validation that already exists**, all chained into `npm run build`:
- `check:memberships`: Power Four and HBCU bucket counts against the acceptance list.
- `check:tuition`: the six Compare tuition rows re-derived from `financialAidReports.ts` bands,
  using `GRADE_BANDS` in `scripts/check_tuition_rows.mjs`.
- `check:ncrows` and `check:ncsuper`: the NC admit-rate rows.
- `check:cup`: the Wells Fargo Cup ledger, plus the three Cup Compare rows.
- `check:schema`, `check:live`, `check:runtime`, `check:cardlink` and others.

**Nothing compares a headline with the list beneath it.** No check covers the pipeline funnel or
bars against the roster, a teaser against its course rows, a camp intro against its rows, or ratio
notation. `check:quals` (`npm run check:quals`, not in the build) only asks whether a coded
Compare cell has a tooltip.

## Decisions

- **One plan, all 13 schools, one PR.** The root causes cross schools (X1–X7), and the check that
  prevents recurrence needs all the data fixed before it can gate.
- **The College Pipeline bars and funnel counts are computed from the roster.** The user prefers
  computed headline numbers over typed ones. Bar counts and widths are numbers, not extracted
  prose, so deriving them changes no overlay unit except where a bar's label itself changes. The
  prose headline stays typed (it is a sentence), and the new check verifies its numbers against
  the derived ones.
- **Other typed counts stay typed and are gated rather than computed.** This covers course
  teasers, camp intros, season headers and Compare cells. They sit inside translated sentences,
  and interpolating a number into nine reviewed locales would invalidate every one of those units
  for no visible gain. The gate gives the same protection: a drift cannot ship.
- **Ratio notation is `~N:1 <group> per counselor` site-wide**, the form every stat tile and
  Compare cell already uses. `1:N` is rejected by the gate. Each computed ratio names its class
  (e.g. "Class of 2027"), so two class sizes on one page stop reading as a contradiction
  (CCD 137 vs 141, DD 50 vs 47).
- **One course-count rule site-wide (X4).** The tile, Compare `us-courses` and the teaser state the
  same number, counted per catalogued course entry (one per level). Where the list collapses a
  sequence into one row, the teaser carries a parenthetical giving the rendered count ("shown here
  as 105 entries: sequences such as French I–V share a row"). This is the convention Covenant and
  Hickory Grove already follow, and it makes CC 143 and Carmel 96 (both USER defaults).
- **Category B never picks a winner.** Both values are shown, each attributed to its page, plus a
  dev-only verify flag, plus an ask where the card has a checklist. The user's brief called this
  a "TO VERIFY flag". By standing rule (`CLAUDE.md`, *Research bookkeeping is dev-only*) the flag
  itself renders on the dev server only. The parent-facing half is the attributed sentence.
- **Category D rows change nothing.** The user ruled on 2026-11-20 that Latin's camp totals (LAT-D1)
  and Gaston Day's camp care (GD-24) stay as is, and Cannon's 251 (CAN-3) was not pursued.
- **Rows are appended, never inserted, wherever order allows.** Overlay `at` paths carry the array
  index, so an insert stales every later unit (memories
  `metric-values-midarray-insert-shifts-paths`, `overlay-at-paths-go-stale-on-row-delete`). Where
  a removal is unavoidable (bars dropped by X1, HG's win-% bars), Phase 2 re-splices the affected
  units.
- **`check:consistency` gates only rules that are at zero after the fixes.** The noun-collision
  scan (R8) stays a report with exit 0. A checker parked at a permanent non-zero count stops
  being read (`CLAUDE.md`, *Testing and verification conventions*).
- **Providence Day's 2026–27 Course of Study IS adopted here** (user, 2026-11-20, reversing the
  first draft's follow-up-plan call). The census in `consistency-data/pd-census.md` was done at
  planning time against both editions, word by word. It found 175 OK rows, 22 non-OK rows and
  11 rows to add. Rows go in catalog order, so Phase 2 re-splices that topic's shifted units.

## Risks

| Risk | Mitigation |
|---|---|
| A fix cascades: a value repeated in a sentence elsewhere stays old | Step 5 greps each school for every old value. R8 catches noun collisions. |
| The bar refactor silently changes a correct school's bars | R2 runs before and after. The 5 already-correct schools (Latin, PD, CCD, CC, Carmel) must render byte-identical bar counts. Compare their `pipelineCounts` against the old typed values in a one-off assertion. |
| Removing bars or rows stales overlay `at` paths | Append wherever possible. Phase 2 step 3 re-splices by stamp. |
| A gate rule parks the build red on a legitimate case | Calibrate R1–R7 against the fixed data to 0 before wiring (step 8). R8 is never a gate. |
| An attributed B sentence reads as the site being unsure | Attribute to the school ("the school's profile says …; its history page says …"). Research bookkeeping stays in the dev-only flag (memory `verify-flags-are-dev-only`). |
| Another session's files get swept into a commit | Explicit-path staging, and `git status --short` before every commit. |
| The live sources change again between planning and implementation | Every re-verified value is in the committed records. Re-fetch a source only if a fix's quoted text no longer matches it. |
