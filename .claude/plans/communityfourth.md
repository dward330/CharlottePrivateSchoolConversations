# Global Community on Campus → 4th card

## Goal

The Global Exposure (`international-travel`) section shows **Global Community on Campus**
as its **4th** card, directly after "Signing Up for Travel". It currently sits 3rd, before
it. The order is shared, so the change applies to every school now and to any school
added later.

It works when both schools render this order:
- **Providence Day** (9 cards): Where They Go → Exchanges & Homestays → Signing Up for
  Travel & GSD → **Global Community on Campus** → Global Learning at Each School Level →
  The Global Studies Diploma → Round Square & the Wider Network → Firsts & Milestones →
  Verdict & Ask the School.
- **Charlotte Country Day** (8 cards): the same order. It has no credential card, and
  its network card is titled "Model UN, WorldQuest & Charlotte's Global Partners".

## Context

- **Card order comes from one array:** `INTERNATIONAL_TRAVEL_CARDS` in
  `src/data/internationalTravel.ts`, at about lines 189–203.
  - `src/pages/SchoolDetail.tsx` (about line 968) renders
    `INTERNATIONAL_TRAVEL_CARDS.filter((c) => itEntry[c.key] != null)`, so each school's
    page follows the array order.
  - The per-school data files' key order (`src/data/internationalTravel/<slug>.ts`) does
    **not** affect rendering. Leave those files alone.
- **The current array:** `trips`, `exchanges`, `community`, `signup`, `start`,
  `credential`, `network`, `milestones`, `verdict`.
  - PR #346 (plan `pdcommunity`, 2026-10-13) moved `community` to 3rd.
  - The user has since said they meant **4th**: after `signup`, before `start`.
- **The comment above the array** narrates the order history. It currently says "The
  user then moved `community` to third place for every school, current and future
  (2026-10-13, pdcommunity)."
- **`src/data/internationalTravel/README.md`, about line 57**, says "`community` is the
  **third** card for every school, after Exchanges & Homestays (user decision,
  2026-10-13)".
- **`.claude/docs/DATA-SCHEMA.md`** is generated by `scripts/gen_data_schema.mjs` and
  lists the cards in registry order.
  - `npm run check:schema` is chained into `npm run build`, so the doc must be
    regenerated or the build fails.
- **`.claude/skills/global-exposure/SKILL.md`** already says to read the live registry
  ("Never list cards from memory"). Future schools inherit the new position with no
  skill edit.
- **Layout:** `community` is a half-width card. `WIDE_TRAVEL_CARDS` holds `trips`,
  `milestones` and `verdict`, and is unchanged.

## Decisions

- **Single-phase:** this adds no user-facing text. No locale catalog or overlay changes,
  and no translation stamp moves, since only the array order changes.
- **"4th" means the 4th registry slot**, after `signup` and before `start`. Every school
  currently has `trips`, `exchanges` and `signup`, so it renders 4th on both schools. A
  future school missing one of those would show it earlier, which is the same
  filter-by-presence behaviour every other card has.
- **The plan name `communityfourth`** was chosen by Claude at the user's invitation.
- **Rewrite the comment and README sentence; don't append.** They should state the
  current order and its date. Shipped history lives in git and in `pdcommunity.md`'s
  Implementation notes.
- **`.claude/plans/pdcommunity.md` is left unchanged.** It is the historical record of
  what PR #346 shipped (3rd place). This plan supersedes that order.

## Approvals needed

**None.** Reordering cards normally needs the user's approval under the UX-design gate.
The user requested this order directly on 2026-10-13: "I want Global Community on Campus
to be the 4th card for everyone." That request is the approval.

`npm run deploy` is **not** part of this plan. Merging is not publishing; deploying needs
its own explicit request.

## Out of scope

- Any other card's position, title, width or content.
- Per-school data files, locale catalogs, overlays.
- Editing the `/global-exposure` skill. It already reads the live registry, so
  `.claude/SKILLS.md` needs no update.
