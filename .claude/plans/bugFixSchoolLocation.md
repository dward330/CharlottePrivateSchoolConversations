# Show each school's real city in the dossier kicker

## Goal

Every school page currently prints the same kicker above the school name:
**"SCHOOL DOSSIER · CHARLOTTE, NC"**. Five of the eleven schools are not in Charlotte, so
those five pages state the wrong municipality. Gaston Day School is in **Gastonia**, not
Charlotte — that is the reported bug, and the research pass found four more with the same
defect.

After this change the kicker reads the school's own published city — `School dossier ·
Gastonia, NC` for Gaston Day, `… · Concord, NC` for Cannon — driven by a per-school data
field rather than a fixed string. We will know it worked when all eleven school pages show
the city in the table below, in every locale.

## Context

**The defect is one string, not eleven.** `src/locales/en.json:152` holds

```json
"dossierKicker": "School dossier · Charlotte, NC"
```

and [SchoolDetail.tsx:442](src/pages/SchoolDetail.tsx#L442) renders it with no per-school
input at all:

```tsx
<p className="dossier-kicker">{tr('school.dossierKicker')}</p>
```

All ten locale catalogs carry their own translated copy of the same key (`ar.json` at line
184, the other nine at line 152), each with the city baked in — including
`ar.json`'s `"ملف المدرسة · شارلوت، نورث كارولاينا"` and `fa.json`'s `"پروندهٔ مدرسه · شارلوت، NC"`,
where **the city name itself is transliterated into the local script**. That is why this is
a two-phase change: the city is not a token that can be dropped into the existing strings
untouched in every locale.

**Where a per-school city belongs.** Two candidate homes were examined:

- `src/data/schools.json` — **rejected.** It is *generated* by the ingest pipeline
  (`.claude/skills/ingest-source-material/SKILL.md`, which regenerates it from
  `source-material/`). A hand-added `city` field would be silently wiped on the next
  ingest, and the `School` type is `{ slug, name }` (`src/lib/types.ts:3`).
- `src/data/brands.ts` — **chosen.** Its header comment states it is
  *"Hand-maintained (NOT regenerated by the ingest pipeline)"*, it is already the per-school
  hand-kept sidecar (`color`, `initials`, `logo`, `welcomeVideoUrl`), and it already has a
  documented fallback path for schools missing an entry (`brandFor`, used via
  `brandOf(slug)` in `src/lib/manifest.ts`). `SchoolDetail.tsx` already calls
  `brandOf(slug)` at line 429, so the value is in hand at the render site with no new import.

**The site-wide "Charlotte-area" phrasing is correct and out of scope.** `home.lede`,
`nav.footerDisclaimer`, `home.eyebrow`, and the meta descriptions in `src/lib/head.ts` all
say "Charlotte-area" or "Charlotte private schools". All eleven schools are in the
Charlotte metro, so those are accurate as written. Only the per-school kicker asserts a
specific municipality.

**The home-page school cards do not show a location** — `src/pages/Home.tsx:112` renders
`home.schoolCardMeta` (topic and document counts) only. No change needed there.

**`src/lib/head.ts` JSON-LD deliberately omits address.** Its comment reads *"Only fields
the repo can populate truthfully. There is no structured address, geo, phone or founding
data in src/data/ — do NOT invent any"*. This plan changes that premise for `city`, but
adding `address` to the JSON-LD is left out of scope (see below) because the pre-rendered
pages are English-only by decision and a partial `PostalAddress` invites a half-populated
schema.

**Caps styling interacts with non-Latin scripts.** `.dossier-kicker` is
`text-transform: uppercase` with `letter-spacing: 0.12em` (`src/index.css:734`), and
`src/index.css:4744` already zeroes the tracking for `bn`, `te`, `fa`, `hi` and `ar`. The
city name flows through that same rule, so no new CSS is needed — but the Arabic and Farsi
strings carry a transliterated city, which is a Phase 2 translation concern, not a styling one.

## Decisions

- **City lives in `src/data/brands.ts`, as a required `city: string` on the `Brand` type** —
  it is the hand-maintained per-school sidecar; `schools.json` is generated and would lose
  the field on the next ingest. Required rather than optional so a newly added school
  cannot silently inherit "Charlotte" by omission — that is exactly how this bug shipped.
- **State stays a separate literal in the locale string, not per-school data** — all eleven
  schools are in NC, and folding "NC" into the data field would force each locale's
  translation of the state abbreviation into `brands.ts`, which is a chrome concern.
- **The kicker becomes an interpolated key `school.dossierKicker` with `{{city}}`** rather
  than a new key name — keeping the key name means the ten existing translations are
  *edited*, not orphaned, and no `check:chrome` "missing key" state is created.
- **`brandFor`'s fallback city is `'Charlotte'`** — it only applies to a slug with no
  `BRANDS` entry, which is already the neutral-slate placeholder path; a new school still
  gets a real city from step 1's required field.
- **Site-wide "Charlotte-area" copy is left alone** — it is accurate for the metro area and
  is not a per-school claim.
- **The source-material record goes in `source-material/branding/_shared/`** — `branding/`
  is a reference folder, not one of the eight research topics in `schools.json`, so the
  ingest pipeline will not turn this file into a research document.

## Out of scope

- Adding `address` / `PostalAddress` / geo data to the JSON-LD in `src/lib/head.ts`. The
  comment there deliberately refuses invented structured data; adding a city-only address
  is a separate decision.
- Changing any site-wide "Charlotte-area" / "Charlotte private schools" copy — it is correct.
- Adding a location to the home-page school cards or the Compare table.
- Street address, ZIP, phone, or a map anywhere in the UI. Only the city is surfaced.
- County or "greater Charlotte" qualifiers in the kicker.

## Steps

Two phases — the kicker is user-facing text and its city is baked into all ten locale
catalogs, including transliterated into Arabic and Farsi script.

### Phase 1 — English

1. **Add `city` to the `Brand` type and every entry** — in
   [src/data/brands.ts](src/data/brands.ts), add `city: string` to the `Brand` type
   (required, not optional) with a short comment explaining it is the municipality in the
   school's own published mailing address and that it drives the dossier kicker. Then set
   it on all eleven `BRANDS` entries using the verified table above: `cannon` → `'Concord'`,
   `carmel-christian` → `'Matthews'`, `covenant-day` → `'Matthews'`, `davidson-day` →
   `'Davidson'`, `gaston-day` → `'Gastonia'`, and `'Charlotte'` for the other six
   (`charlotte-catholic`, `charlotte-christian`, `charlotte-country-day`, `charlotte-latin`,
   `hickory-grove-christian`, `providence-day`).

2. **Give the fallback a city** — in the same file, `brandFor()` builds a placeholder Brand
   for slugs with no entry. Add `city: 'Charlotte'` there so the return type stays valid.
   Note in a comment that this path is for unknown slugs only; real schools get a real city
   from `BRANDS`.

3. **Interpolate the city into the English kicker** — in
   [src/locales/en.json:152](src/locales/en.json#L152) change
   `"dossierKicker": "School dossier · Charlotte, NC"` to
   `"dossierKicker": "School dossier · {{city}}, NC"`. Keep the key name.

4. **Pass the city at the render site** — in
   [SchoolDetail.tsx:442](src/pages/SchoolDetail.tsx#L442) change
   `{tr('school.dossierKicker')}` to `{tr('school.dossierKicker', { city: brand.city })}`.
   `brand` is already in scope from `const brand = brandOf(slug)` at line 429, so no new
   import or lookup is needed.

5. **Leave the other nine catalogs on their current strings for now** — they still render
   their hardcoded city, which is the intended English-first state: the English page is
   correct and reviewable, and the nine other locales are visibly unchanged until Phase 2.
   Do not touch them in this phase.

**→ STOP. `/implement` ends its turn here and waits for the user's review.** Nothing below
runs until they confirm the English kicker reads the way they want on all eleven pages.

### Phase 2 — Every other locale

UI chrome only — this is the `src/locales/*.json` catalog layer per `TRANSLATED` in
[src/lib/i18n.ts:108](src/lib/i18n.ts#L108). The research-prose overlay layer
(`PROSE_TRANSLATED`) is **not** involved: `dossierKicker` is chrome, not `src/data` prose,
so no overlay rebuild, no `i18n:build`, and no work-file extraction is needed.

1. **Convert the nine remaining catalogs to `{{city}}`** — in each of `ar.json`, `bn.json`,
   `es.json`, `fa.json`, `fr.json`, `hi.json`, `ht.json`, `it.json`, `te.json`, replace the
   baked-in city in `school.dossierKicker` with the `{{city}}` placeholder, preserving each
   locale's own separator, word order and state rendering. Note the key is at line 184 in
   `ar.json` and line 152 in the other eight. Current values for reference:

   | Locale | Current | Becomes |
   | --- | --- | --- |
   | `es` | `Expediente escolar · Charlotte, NC` | `Expediente escolar · {{city}}, NC` |
   | `fr` | `Dossier d'école · Charlotte, NC` | `Dossier d'école · {{city}}, NC` |
   | `it` | `Dossier della scuola · Charlotte, NC` | `Dossier della scuola · {{city}}, NC` |
   | `ht` | `Dosye lekòl · Charlotte, NC` | `Dosye lekòl · {{city}}, NC` |
   | `bn` | `স্কুল নথি · Charlotte, NC` | `স্কুল নথি · {{city}}, NC` |
   | `te` | `పాఠశాల సంపుటి · Charlotte, NC` | `పాఠశాల సంపుటి · {{city}}, NC` |
   | `hi` | `स्कूल दस्तावेज़ · Charlotte, NC` | `स्कूल दस्तावेज़ · {{city}}, NC` |
   | `fa` | `پروندهٔ مدرسه · شارلوت، NC` | see step 2 |
   | `ar` | `ملف المدرسة · شارلوت، نورث كارولاينا` | see step 2 |

2. **Decide and apply the Arabic and Farsi city-name policy — the one real judgment call.**
   Both currently *transliterate* the city into local script (`شارلوت` = Charlotte), and
   `ar` also spells out the state (`نورث كارولاينا`). A `{{city}}` interpolation injects the
   **Latin** city name from `brands.ts`, so those two locales would render Latin "Gastonia"
   inside Arabic-script text. Two options, and the plan's default is (a):

   - **(a) Interpolate Latin, keep the rest localized** — `ملف المدرسة · {{city}}، نورث كارولاينا`.
     Consistent with the project's standing rule that searchable identifiers stay Latin
     (`Upper School`, `AP`, `GPA`), and a parent matching the school against a map or the
     school's own site sees the same Latin name. **Note this changes `شارلوت` → `Charlotte`
     for the six Charlotte schools in `ar`/`fa`** — a deliberate consequence, not a
     regression. The `ar` native review (memory: Arabic rollout, where `تشارلوت` was
     corrected to `شارلوت`) settled the *spelling* of the transliteration; this changes
     whether it is transliterated at all, so flag it to the user rather than deciding
     silently.
   - **(b) Add a per-locale city map** — keeps Arabic script but requires transliterating
     five new city names (Gastonia, Concord, Matthews, Davidson) into `ar` and `fa` with no
     native reviewer for the new names, and adds a second translation surface for city
     names. Rejected as disproportionate unless the user prefers it.

   Since RTL is involved, wrap the interpolated Latin city per the existing bidi rule if it
   renders adjacent to neutral characters — but note `{{city}}` here is a **strong-L Latin
   identifier** sitting beside a comma, which per the CLAUDE.md RTL note needs no isolate
   (isolates are for bidi-*neutral* figures). Verify in the browser rather than assuming.

3. **Confirm no other catalog string bakes in a per-school city** — grep the ten catalogs
   for `Charlotte` and check each hit is site-wide copy (`nav.brandName`, `home.lede`,
   `home.eyebrow`, `nav.footerDisclaimer`, `podcast.showName`) and not a per-school claim.

## Risks

| Risk | Mitigation |
|---|---|
| A locale keeps its baked-in city and silently renders "Charlotte" for Gaston Day | The Phase 2 browser sweep loads `gaston-day` in all ten locales specifically to catch this; `check:chrome` cannot see a *wrong* value, only a missing key |
| Arabic/Farsi lose their transliterated city as a side effect | Called out as an explicit decision in Phase 2 step 2 with the `ar` native review noted — surface it to the user rather than shipping it silently |
| A future school is added with no `city` and inherits "Charlotte" | `city` is **required** on the `Brand` type, so `tsc` fails; this is precisely the omission that produced the original bug |
| The `_shared` folder gets treated as a school slug by some script | `branding/` is not a topic in `schools.json` and no script enumerates it; verified at planning time. Confirm `npm run build` and `npm run check:schema` stay green after committing the file |
